授權與防複製

適用對象：系統管理者  |  最後更新：2026-10

授權免費，一次取得、永久有效。授權會綁定執行系統的那台電腦，目的是讓系統被整個複製到別台電腦時無法直接使用，保護貴公司自己的部署。 綁定方式依部署類型而不同；系統會自動判斷，申請時不必自己選。

1. 三種部署的授權方式

部署授權綁定需要連線嗎被整個複製到別台電腦時
實體機（Windows／Linux）這台電腦的主機板識別碼不需要（可自選加上線上確認，第 3a 節）硬碟裝到別台：識別碼不同，系統不連資料庫，只顯示授權頁
WSLWindows 主機的主機板識別碼不需要（可自選加上線上確認，第 3a 節）匯出到別台電腦：識別碼不同，系統不連資料庫，只顯示授權頁
虛擬機（VM）、容器每 90 天由管理員確認一次系統本身不連外；由管理員的瀏覽器代為確認第二份來確認會被拒絕，最多用到它下次確認日，之後唯讀

虛擬機的硬體識別碼寫在虛擬機的設定檔裡，可以被改掉，所以改用定期確認。即使拿到的是綁主機板的授權，系統只要偵測到自己跑在虛擬機或容器裡，一樣要定期確認。重灌作業系統、更新 BIOS 不會改變主機板識別碼。

2. 申請授權

1
先在正式主機產生機器錨定碼：執行 SmartFactory.MES.MachineId --init（Linux 須以 root 執行）。Linux 實體機請先完成第 4 節的設定，否則讀不到主機板識別碼。
2
取得申請碼（內含環境指紋、主機識別碼、部署類型，皆為雜湊值）：
  • 全新安裝：還沒有授權時系統無法啟動，也就開不了「授權狀態」頁。請在正式主機執行 SmartFactory.MES.MachineId（不加參數），畫面會印出部署類型、主機識別碼、申請碼、登記網址（第一次申請）與換發網址（已有授權、換電腦或主機板）。
  • 系統已在運作（換發、加一台）：以管理員開啟「授權狀態」頁（/License），頁面顯示部署類型、主機識別碼、適用的授權方式與申請碼。
  • 開啟網址只看到授權頁（換了電腦或主機板）：授權頁上就有這台電腦的申請碼與換發網址。
3
用任何能上網的電腦或手機開啟登記網址（「授權狀態」頁為「申請授權（開啟登記頁）」按鈕；換電腦、換主機板請改用換發網址，或按「申請換發（換電腦、換主機板）」，另需填原授權編號），填寫公司與聯絡資料送出；或把申請碼整串交給導入顧問代為申請。首次登記由授權提供者人工審核，約需數個工作天，授權檔以 Email 寄出。
4
收到授權信後，依第 2a 節的情況處理。
只提供申請碼，不要提供錨定碼（--raw 才會顯示、長得像 UUID 的那串）——它是資料庫連線字串加密的金鑰材料。

2a. 收到授權信之後

信件附件是授權檔（檔名可能是 license-貴公司代碼.json，放到系統時一律改名為 license.json）。先打開確認 licenseId（授權編號），再依目前情況擇一處理：

目前情況要做什麼
全新安裝（系統還沒啟動過） ① 把 license.json 放到應用程式目錄；Security DLL 從 GitHub Releases 下載與系統同版本的檔案，放在 Security/SmartFactory.MES.Security.dll（授權信只附授權檔；系統會拒收舊版 DLL，升級系統時一併更換）。
② 由 IT 在這台正式主機上，以這份授權的授權編號加密資料庫連線字串（工具 EncryptConnectionString，加 --this-host；VM／容器的授權沒有主機識別碼，改加 --no-host-binding），結果填入設定檔的 ConnectionStrings:DefaultEncrypted。連線字串的金鑰包含這台主機的主機板識別碼，只能在這台主機上產生，授權提供者無法代為加密。
③ 啟動服務，以管理員開啟「授權狀態」頁確認授權編號正確、主機比對「符合」。
④ 虛擬機／容器：按一次「確認授權」（第 3 節）。
系統已在運作，新授權的授權編號與現行相同「授權狀態」頁 →「匯入新授權」上傳。系統先驗證，通過才取代現行授權，不需重新啟動。
系統已在運作，授權編號不同（換電腦、換主機板、改授權方式）「匯入新授權」會拒絕（訊息「新授權的編號與現行不同…」），因為資料庫連線字串是以授權編號加密的。請由 IT 依上面「全新安裝」的 ②，以新授權編號重新加密連線字串，替換 license.json，再重新啟動服務。
開啟網址只看到授權頁（換了電腦或主機板）同上一列：重新加密連線字串、替換 license.json、重新啟動。
  • 不可修改授權檔：每個欄位都在數位簽章範圍內，改了就無法使用（「授權檔案簽章無效」）。內容有誤請聯繫授權提供者重新核發。
  • 授權信、授權檔與機器錨定檔請一併備份；錨定檔遺失或重新產生，就要重新申請授權。
  • 啟動失敗時請看服務日誌：「找不到授權檔案」＝檔案位置不對；「連線字串為 ENC:v3…但此授權沒有列主機識別碼」＝授權沒有主機識別碼卻用了 --this-host，改用 --no-host-binding 重新加密。

3. 虛擬機：每 90 天確認

虛擬機的授權每 90 天要確認一次。到期前 14 天開始，管理員登入後會看到提醒；逾期未確認，系統轉為唯讀（可查詢、不能新增修改），確認後立即恢復。

1
以管理員開啟「授權狀態」頁，在「授權確認（每 90 天）」區塊按「確認授權」。
2
瀏覽器會開啟授權伺服器的確認頁。顯示「確認完成」後，結果會自動傳回系統，原頁面重新整理並顯示新的有效期限。確認頁可關閉。
這台電腦不能上網時：按「複製確認連結」，把連結傳到手機或其他能上網的裝置開啟；確認完成後按「下載回覆檔」， 把檔案傳回這台電腦，在「授權狀態」頁的「匯入確認回覆」上傳。
  • 確認頁顯示「已由另一份系統確認過」：同一份授權正在別處使用，常見於虛擬機被複製。若是合法搬遷，請聯繫授權提供者申請轉移。
  • 客戶若允許系統直接連外，可在 appsettings.json 設定 "License": { "Transport": "direct" }，系統會每日自動確認，不需人工操作。

3a. 線上授權確認（自選）

實體機與 WSL 預設只做離線驗證。若希望再多一層保護，可以啟用「線上授權確認」：啟用後，這台電腦的授權也要每 90 天確認一次，做法與第 3 節相同。 整台複製到別處的副本無法通過確認。

1
以管理員開啟「授權狀態」頁，先在「授權確認」區塊按「確認授權」完成一次確認。
2
在「線上授權確認」區塊按「啟用線上授權確認」。沒有先完成確認時，這個按鈕無法按。
  • 連不上授權伺服器不會影響使用，只有超過確認期限（確認後 90 天）仍未再次確認，系統才轉為唯讀；到期前 14 天開始提醒。
  • 不再需要時可按「停用線上授權確認」，改回只做離線驗證。
  • 虛擬機與容器：一律要確認，畫面顯示「已啟用（虛擬環境強制）」，無法停用；直接修改資料庫也無效。

4. Linux 與容器的設定

Linux 的主機板識別碼只有系統管理員權限讀得到，而 MES 以一般服務帳號執行。請在 systemd 服務檔的 [Service] 區段加入下面這一行，讓系統每次啟動前以管理員權限把識別碼寫到記憶體中的暫存區：

ExecStartPre=+/bin/sh -c 'mkdir -p /run/smartfactory && cat /sys/class/dmi/id/product_uuid > /run/smartfactory/host-id'

加入後執行 sudo systemctl daemon-reload 並重新啟動服務。/run 不在硬碟上，複製硬碟不會帶走它；換到別台電腦開機時會寫入那台的識別碼。

容器：一律每 90 天確認（不綁主機、不讀主機識別碼，掛載宿主的識別碼也不會改變）。機器錨定檔與授權確認結果存在 docker-compose.yml 的 anchor volume，容器重建不受影響；刪掉這個 volume 就等於換了一台機器，要重新申請授權，請納入備份。申請碼與連線字串加密用映像內附的工具（docker compose run --rm --no-deps --entrypoint dotnet app tools/MachineId/SmartFactory.MES.MachineId.dll），連線字串加密要加 --no-host-binding。

WSL：系統透過 Windows 的 reg.exe 讀取 Windows 主機的識別碼。若授權狀態頁顯示「無法執行 Windows 的 reg.exe」，通常是 WSL 與 Windows 的互通被停用，執行 sudo systemctl restart systemd-binfmt 或重新啟動 WSL 即可。讀不到時系統無法確認這是授權的電腦，同樣不連資料庫、只顯示授權頁；修好後重新啟動服務即恢復。

5. 換電腦、換主機板、搬家

情況要做什麼
重灌作業系統、更新 BIOS不需處理（主機板識別碼不變）。重灌時請保留或還原錨定檔。
換電腦、換主機板系統不連資料庫，開啟網址只會看到授權頁（含新電腦的申請碼）。開啟授權頁上的換發網址重新申請（填原授權編號）；收到新授權後依第 2a 節，請 IT 在新電腦上以新授權編號重新加密資料庫連線字串（連線字串的金鑰與主機板綁定），再重新啟動。
虛擬機搬到另一台主機先聯繫授權提供者申請轉移，再於新位置按「確認授權」。
原本的電腦還在用、要再加一台每台電腦各需一份授權，請另行申請。

6. 授權狀態與唯讀

  • 正常：所有功能可用。
  • 提醒：功能不受影響，但有事要處理，例如虛擬機的確認快到期。管理員畫面上方會顯示橫幅。
  • 唯讀：可登入、查詢、列印報表，不能新增、修改、過帳；背景排程也會暫停寫入。 發生於虛擬機或已啟用線上授權確認的電腦逾期未確認、授權被撤銷。處理完成（匯入新授權、完成確認）後立即恢復。
  • 只顯示授權頁：主機識別碼不符（「此授權不屬於這台電腦」，例如整台硬碟或 WSL 被複製到別台）或讀不到時，系統不連資料庫、不提供登入，任何網址都只顯示原因與申請碼——被複製出去的環境看不到任何資料。換回原電腦、修好讀取或換上新授權後重新啟動即恢復。

7. 會傳送什麼、不會傳送什麼

時機傳送的內容
平常運作（每天一次，所有部署）不傳送任何資料：系統只讀取 raw.githubusercontent.com 上公開的終止聲明檔（作者停止維護時，用它永久解除授權限制），讀不到也不影響使用。
申請授權（登記頁）您填寫的公司與聯絡資料、機器指紋、主機識別碼、部署類型、系統版本。指紋與主機識別碼都是雜湊值，無法還原成錨定碼或主機板序號。
虛擬機、或已啟用線上授權確認的電腦每 90 天確認授權檔、機器指紋（雜湊）、啟用碼、系統版本、作業系統、時間。由管理員的瀏覽器送出，系統本身不連外。送出的完整內容可在「授權狀態」頁的「確認時會送出什麼？」逐字檢視。

任何時候都不會傳送：錨定碼、主機板序號原值、資料庫連線字串、帳號密碼，以及任何工單、庫存、客戶、財務等業務資料或個人資料。

系統原始碼公開，貴公司資訊人員可自行檢查上述行為。防火牆設定：伺服器只需放行 raw.githubusercontent.com（也可以不放行，只是讀不到終止聲明）；授權伺服器 license.gemba-mes.workers.dev 由管理員的瀏覽器連線，伺服器本身不需放行。
