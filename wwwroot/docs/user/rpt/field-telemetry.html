現場遙測Field Telemetry

路由：/FieldTelemetry  |  手機上發生、伺服器看不到的事：頁面錯誤、API 慢或連不上、斷線、未送出的資料Route: /FieldTelemetry  |  What happens on the phones that the server cannot see: page errors, slow or unreachable APIs, disconnections, unsent data

現場回報「手機很慢」「按了沒反應」「報工不見了」時，伺服器的紀錄只看得到請求到了的那一半。頁面腳本出錯、請求根本沒送到、訊號弱到每支 API 都要等十幾秒、手機裡卡著好幾筆沒送出的報工——這些都發生在手機上。每支手機每分鐘會把這些狀況回報一次，本畫面把它們彙總起來。When the floor reports "the phone is slow", "nothing happens when I tap" or "my report disappeared", the server's records only show the half where the request arrived. A script error on the page, a request that never got through, a signal so weak that every API takes over ten seconds, entries stuck unsent on a phone — all of that happens on the phone. Every phone reports these once a minute, and this screen brings them together.

畫面內容Screen contents

1
右上角選期間：最近 24 小時、7 天或 30 天。Pick the period at the top right: the last 24 hours, 7 days or 30 days.
2
四張 KPI 卡：頁面錯誤次數；API 超過 3 秒的比例（下方附連不上或失敗的次數，超過 5% 轉黃）；斷線次數與合計分鐘；有資料未送出的手機數（有就轉黃）。Four KPI cards: the number of page errors; the share of API calls over 3 seconds (with the number that were unreachable or failed underneath; turns amber above 5%); the number of disconnections and their total minutes; and the number of phones with unsent data (amber if there are any).
3
手機現況：每支手機最後一次回報的時間、使用者、網路類型與延遲、版本，以及還有幾筆沒送出、最舊的等了幾分鐘。有未送出資料的排在最上面、以黃底標示——那支手機的人可能以為已經報過了。Phones: for each phone, when it last reported, who was using it, network type and latency, version, and how many entries are still unsent and how long the oldest has waited. Phones with unsent data are listed first with an amber background — the person using it may believe the work has already been reported.
4
頁面錯誤排行：同一則錯誤在哪一頁、發生幾次、幾支手機遇到、最後一次是什麼時候。同一則錯誤很多支手機都遇到，通常是程式問題而不是個別手機的問題。Top page errors: for each error, the page, how often it happened, on how many phones and when it was last seen. An error that many phones hit is usually a software problem rather than a problem with one phone.
5
API 耗時與失敗：各支 API 的呼叫數、平均與最長耗時、3～10 秒與 10 秒以上的次數、連不上或失敗的次數，以及衝突次數（別人同一刻改了同一張單、系統自動重試 3 次仍衝突；那一筆沒存進去，手機會再送一次）。衝突常出現在某幾條線，表示那幾條線常有多人同時操作同一張派工。有失敗或超過 10 秒的整列標紅。網址裡的單號、機台代號等一律顯示成 {id}，同一支 API 才彙總得起來。API response times and failures: for each API, the number of calls, average and longest time, how many took 3–10 seconds or over 10 seconds, how many were unreachable or failed, and how many conflicts there were (someone else changed the same document at the same moment and three automatic retries still conflicted; that entry was not saved and the phone sends it again). Conflicts concentrated on a few lines mean several people there often work on the same dispatch at once. Rows with failures or calls over 10 seconds are shown in red. Document numbers, machine codes and the like in the address are shown as {id}, so that calls to the same API add up.
6
最近事件：逐筆列出錯誤、斷線與佇列回報，可依種類篩選；錯誤可展開「細節」看堆疊。Recent events: each error, disconnection and queue report one by one, filterable by kind; expand "Details" on an error to see the stack trace.

怎麼看How to read it

  • 某條產線一直說慢：看「手機現況」那幾支的網路與延遲；延遲幾百毫秒以上、或 API 表裡同一時段大量 3 秒以上，多半是那一區的 Wi-Fi 訊號，不是系統。One line keeps saying it is slow: check network and latency for those phones under "Phones"; latency of several hundred milliseconds, or many calls over 3 seconds in the API table at the same time, usually points to the Wi-Fi in that area rather than the system.
  • 只有一支 API 慢：其他 API 都正常、只有它慢，是伺服器端那支查詢的問題，請轉給系統維護。Only one API is slow: if everything else is fine and only that one is slow, the query behind it on the server is the problem — pass it to system maintenance.
  • 手機有未送出的資料很久了：請那位使用者打開手機首頁的待送出清單；超過 30 分鐘的會停在「待確認」，要本人按「確認送出」或「捨棄」（見手機手冊「斷線保護」）。A phone has had unsent data for a long time: ask that user to open the waiting list on the phone's home page; anything older than 30 minutes stops at "awaiting confirmation" until they tap "Confirm and send" or "Discard" (see "Disconnection protection" in the mobile manual).

注意事項Points to note

時間一律是伺服器收到回報的時間（手機時鐘不可信），所以斷線期間發生的錯誤會在恢復連線後才出現。畫面顯示目前廠別，加上沒有廠別的回報（例如登入頁出錯、工作階段已過期時）。不收任何請求內容；手機代號是手機瀏覽器自己產生的隨機碼，不是硬體識別碼，清除瀏覽器資料後會換一個。資料保留 30 天，逾期自動清除。本畫面預設只有管理者、總部、經理與財務角色看得到。All times are when the server received the report (phone clocks are not trusted), so errors that happen while a phone is offline only appear after it reconnects. The screen shows your current plant plus reports with no plant (for example errors on the sign-in page, or after a session expired). No request content is collected; the phone code is a random value the phone's browser generates itself, not a hardware identifier, and it changes if the browser data is cleared. Data is kept for 30 days and then cleared automatically. By default only the Admin, HQ, manager and finance roles can see this screen.
