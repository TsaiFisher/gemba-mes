常用查詢Saved Queries

把一組查詢條件存起來，下次一鍵重跑Store a set of query criteria and re-run them with one click

報表畫面的查詢列上方若出現「我的常用查詢」與「儲存此查詢」，表示這張報表支援常用查詢。它解決的是「每次都要重設一次同樣的條件」——存一次之後，下拉選它就會帶著條件重新查一次。When "My saved queries" and "Save this query" appear above a report's search bar, that report supports saved queries. They solve the chore of re-entering the same criteria every time: save once, then pick it from the dropdown to re-run with those criteria.

怎麼用How to use it

1
在報表畫面先把查詢條件設好並查詢一次，確認結果是你要的。Set the criteria on the report and run the search once, to confirm the result is what you want.
2
點「儲存此查詢」，取一個看得懂的名字（例如「A 廠上月逾期採購」），並選一個期間（見下方說明）。Click "Save this query", give it a name you will recognise (for example "Plant A overdue purchases last month"), and pick a period (see below).
3
之後從「我的常用查詢」下拉選取即可重跑。不需要的用下拉裡的刪除鈕移除。From then on, pick it from the "My saved queries" dropdown to re-run. Remove ones you no longer need with the delete button in the dropdown.

期間存的是「上個月」，不是「2026-08-01 ~ 2026-08-31」The period is stored as "last month", not as a fixed date range

這是刻意的設計，也是常用查詢唯一的必填欄位This is deliberate, and it is the one field you must fill in

吃期間的報表在存檔時一定要選一個相對期間（今天／上週／上個月／本季…）。存成固定日期的「上月銷售排行」，下個月點開還是上個月的資料——那正好是常用查詢的反面。選了相對期間，每次點開都會重新換算成當下的那一段。Reports that take a period require a relative period when saved (today, last week, last month, this quarter…). A "last month's sales ranking" stored as fixed dates would still show that same month when opened next month — the opposite of what a saved query is for. With a relative period it is recalculated each time you open it.

有些報表的期間選項比較少，那是刻意收窄的Some reports offer fewer period options, deliberately
  • 會計／財報類（資產負債表、損益表、試算表）只給「本會計期間／上一會計期間」。會計期間可以自訂起訖、與日曆月不同；存成「上月」雖然也跑得動，但在自訂期間的廠別，它不會是你以為的那一期。Accounting and financial statements (balance sheet, profit and loss, trial balance) offer only "this accounting period / last accounting period". Accounting periods can have custom start and end dates that differ from calendar months, so "last month" — although it would run — would not be the period you had in mind at a plant using custom periods.
  • 年度型（採購金額分析）只給「今年／去年」。這張畫面選的是一個年度、看 12 個月，存成「上月」會靜靜變成一整年。Annual reports (purchase amount analysis) offer only "this year / last year". That screen selects a year and shows twelve months, so "last month" would quietly widen into a whole year.

權限與範圍Permissions and scope

項目Item說明Guide
誰看得到Who can see them常用查詢是個人的，只有自己看得到，不會分享給同部門或同角色Saved queries are personal: only you see yours; they are not shared with your department or role
權限怎麼算How permission is checked每次點開都以當下的你重新判定權限。權限被調整後，舊的常用查詢會擋下來並顯示原因，不會沿用存檔當時的權限Permission is re-evaluated as you are now every time you open one. If your permissions change, an old saved query is blocked with a reason rather than running under the permissions it was saved with
存了哪些條件Which criteria are stored只存該報表查詢列上看得到的欄位。畫面表達不了的條件不會被存進去，存檔時會告訴你丟掉了哪些Only the fields visible on that report's search bar. Criteria the screen cannot express are not stored, and you are told which were dropped when you save
廠別Plant不存在常用查詢裡。重跑時一律用你當下切換的廠別，所以同一張常用查詢在不同廠會查出該廠的資料Not stored. A re-run always uses the plant you are currently switched to, so the same saved query returns that plant's data

哪些報表有Which reports have it

支援常用查詢的報表目前有 22 張，涵蓋庫存、訂單、採購、委外、製造、會計與財報。判斷方法很直接：查詢列上方有沒有那兩顆按鈕——沒有就是這張報表還沒納入，不是你的權限問題。Twenty-two reports currently support saved queries, across inventory, sales, purchasing, outsourcing, manufacturing, accounting and financial statements. Telling them apart is straightforward: look for the two buttons above the search bar. If they are absent the report has not been included yet — it is not a permission problem.

存成常用查詢之後，才能加排程A saved query comes first, then a schedule

要讓報表定期自動產生並寄給指定收件人，流程是先存成常用查詢，再到「報表排程」加排程。沒有「直接把這次查詢變成排程」的捷徑，這是刻意的——排程會反覆執行，值得先確認一次條件是對的。To have a report produced automatically and sent to recipients, the flow is save it as a saved query first, then add a schedule under "Report Schedules". There is deliberately no shortcut that turns the current search straight into a schedule: a schedule runs again and again, so it is worth confirming the criteria once first.
