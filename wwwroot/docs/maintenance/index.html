系統維護手冊

適用對象：系統顧問 / 企業 MIS  |  SmartFactory MES v1.x

系統架構概覽

SmartFactory MES 為 ASP.NET Core 10 MVC 架構，採用 Razor Pages 混合 Area/Module 模式，後端以 EF Core 連接 PostgreSQL 資料庫。

Solution 組成（三個 Projects）
  • Core（SmartFactory.Core）— 跨應用共用框架：Entity 基礎類別、簽核引擎、多語系、選單架構、共用 UI 元件
  • ProjectZ（SmartFactory.MES）— MES 應用主體：所有業務模組（BAS/PUR/INV/ORD/MFG/OUT/QCR/FIN）
  • Tests（SmartFactory.MES.Tests）— 整合測試 + 慣例測試

資料庫設計重點

命名規則

  • 資料表：蛇底線複數，如 purchase_orders、inventory_reservations
  • 主鍵：Id（GUID，HasDefaultValueSql("gen_random_uuid()")）
  • 廠別：實作 IPlantEntity（含 PlantId FK）
  • 資料授權：實作 IDataAuthEntity（含 CreatedByUserId）
  • 時區：所有日期時間欄位使用 UTC，PostgreSQL 儲存為 timestamp with time zone

慣例測試規則

位於 Tests/Conventions/ConventionTests.cs，新畫面必須符合下列規則，否則 CI 紅燈：

規則說明修正方式
R6 Index.cshtml 含 openPanel( 的畫面，必須在 Scripts section 包含 _CrudPanelScripts 加入 @section Scripts { @await Html.PartialAsync("_CrudPanelScripts") ... }
R6c _Form.cshtml 動態新增列（appendChild/insertAdjacentHTML）含 input 時，必須呼叫 armValidation( 在 appendChild 後加 armValidation(document.getElementById('formId'));
R7 Controller 的訊息字串（message=、AddModelError、TempData[）不得含硬編碼中文字 將訊息移至 ProjectZSharedResource.zh-TW.resx，以 _loc["Key"].Value 引用
R11 使用 PaginatedList 的 Index.cshtml 必須在檔案內有 Model.PageIndex 或 Model.HasNextPage 使用 inline pagination 而非 _Pagination.cshtml partial

新增模組畫面標準流程

使用 /new-screen 指令（Claude Code Skill）可自動產生符合所有慣例的骨架程式碼。

手動新增時需完成以下步驟：

  1. 建立 Entity（Modules/XXX/Models/），實作 IPlantEntity
  2. 在 partial DbContext（Data/XXX_DbContext.cs）加入 DbSet
  3. 建立 Service（interface + implementation，含 CRUD）
  4. 在 Program.cs 或 DI 設定中 AddScoped 注入 Service
  5. 建立 Controller（繼承 Controller，注入 Service + IStringLocalizer<ProjectZSharedResource>）
  6. 建立 Views（Index.cshtml + _Form.cshtml），確認符合 R6/R6c/R7/R11
  7. 在多語系 resx 加入操作訊息 key（中英兩份）
  8. 登錄選單（見下節）
  9. 建立 EF Migration
  10. 執行慣例測試確認全部通過

選單登錄

新畫面必須同時在以下兩處登錄，否則選單不顯示：

  1. ProjectZMenuContributor.cs：加入 context.Menu.AddItem(...)，MenuKey 須與 Controller Area/Name 對齊
  2. Resources/ProjectZSharedResource.zh-TW.resx 與 en-US.resx：加入選單顯示名稱的 key
MenuKey 格式：Menu.模組.畫面名，例如 Menu.INV.MaterialStaging。兩份 resx 都要加，否則另一語系顯示空白。

多語系 / 在地化

系統支援繁體中文（zh-TW）與英文（en-US），採雙軌架構：

resx 檔管理者用途
Core/Resources/CoreSharedResource.*.resx Core Project 框架通用字串（審核、退回、儲存⋯）
ProjectZ/Resources/ProjectZSharedResource.*.resx ProjectZ 業務模組訊息、選單名稱、欄位錯誤

重要規則：BAS 模組（及其他模組）不得自行 register localization provider；所有欄位驗證 key 應加入 Core SharedResource，避免重複註冊導致衝突。

簽核機制

Core 提供統一的簽核引擎，業務單據（如採購單、庫存調整單）在以下狀態流中移動：

Draft → PendingApproval → Approved / Rejected
         （送審）          （核准/退回）
Approved / Rejected → Draft （撤回 / 重送）

Controller 中判斷是否需走簽核時，讀取「文件簽核設定」（ApprovalTemplate）。若未設定範本，則視為免簽核，直接核准。

過帳（PostLineDetailAsync / 確認單據）的入口，應統一檢查 ApprovalStatus == Approved，確保未簽核單據無法過帳。

庫存預留機制

詳細規格見 .claude/specifications/inventory-advanced.md。簡要說明：

  • ReservationSourceType：MrpRunLine(0) / WorkOrderMaterial(1) / Dispatch(2) / MaterialStagingOrder(3)
  • ReservationStatus：Active（佔用可用量）/ Released / Consumed
  • inv_simplified_mode（系統參數）：true = 入庫核准即過帳；false = 全模式需完成上架
  • MRP Fstock 在全模式下會加入 pendingPutAway − pendingPick 修正值

代碼維護機制（CodeEntry）

各畫面的 select 下拉選單，資料來源統一從 CodeEntry 依 Category 篩選：

// 在 Service 中取得選項
var options = await _context.CodeEntries
    .Where(c => c.Category == "PZ.ScrapReason" && c.IsActive)
    .ToDisplayOptionsAsync();

// 在 View 中使用
@Html.DropDownListFor(m => m.ReasonCode, ViewBag.ReasonOptions as SelectList, ...)

新增代碼類別時，僅需在「代碼維護」畫面新增對應 Category 的記錄，無需修改程式碼。

目前使用中的 Category 清單見《上線設定清單 §2》。

資料庫 Migration

注意 Snapshot 漂移問題：每次產生 Migration 前，先確認工作目錄無未提交的 Entity 變更， 否則 EF Core 可能誤生虛假欄位增刪。Migration 產生後需肉眼確認 Up() 和 Down() 的內容合理。

常用指令

# 在 ProjectZ 目錄下執行
dotnet ef migrations add MigrationName --project SmartFactory.MES --startup-project SmartFactory.MES
dotnet ef database update --project SmartFactory.MES --startup-project SmartFactory.MES

# 若需回退
dotnet ef database update PreviousMigrationName

Seed 資料

初始種子資料（授權設定、預設角色）在 Data/SeedData.cs 中，需確認 FK 參照正確，否則 CI 中的 Clean DB 測試會失敗。

CI / 測試

測試以 xUnit 撰寫，分兩類：

類型說明執行指令
慣例測試（Convention） 靜態掃描 .cshtml/.cs 確認符合 R6/R6c/R7/R11 規則 dotnet test --filter "FullyQualifiedName~ConventionTests"
整合測試 使用 InMemory / SQLite DB 驗證 Service 邏輯 dotnet test
UITests（Playwright）使用 :5110 port。若 CI 顯示 port 不符錯誤（:5000 vs :5110）， 是 port 設定問題而非真正回歸，以 --urls http://0.0.0.0:5110 啟動應用即可。

Baseline 慣例測試注意事項

  • Baseline 以檔案路徑為 key（不用 file:line 格式）
  • 不得在工作樹有未提交變更時重建 baseline，以免納入暫時性差異

備份與還原

備份不只有資料庫。排程報表的產出檔與上傳檔（公司 logo 等）存在檔案系統上，不在資料庫裡。 只還原資料庫的話，ReportRun 的紀錄會在、檔案不在，使用者點下載一律 404。 請一律使用 scripts/backup-db.sh，它會在同一次執行、同一個時間戳下產出資料庫與檔案兩份產物。

執行備份

# 用預設值（連線走標準 PG 環境變數，密碼建議放 ~/.pgpass）
scripts/backup-db.sh

# 生產環境典型設定
PGHOST=db PGDATABASE=SmartFactoryMES \
REPORTS_PATH=/var/lib/smartfactory/reports \      # 即組態 Reports:StoragePath
UPLOADS_PATH=/var/www/smartfactory/wwwroot/uploads \
BACKUP_DIR=/backup/mes RETENTION_DAYS=30 \
BACKUP_GPG_RECIPIENT=backup@corp.com \            # 加密（產物 .gpg，明文即刪）
BACKUP_RCLONE_REMOTE=offsite:mes-backups \        # 異地
scripts/backup-db.sh

產出兩份共用時間戳的產物（未設加密時沒有 .gpg 尾綴）：

  • <DB>-<時間戳>.dump.gpg——資料庫（pg_dump -Fc，加密前已用 pg_restore --list 驗過完整性）
  • <DB>-<時間戳>-files.tar.gz.gpg——報表檔與上傳檔，包內是相對路徑（reports/、uploads/）

目錄不存在時腳本會出聲警告並只備資料庫，不算失敗——但那行警告要當回事， 「以為有備到檔案」通常撐到還原當天才會發現。設 UPLOADS_PATH=- 可明確跳過。

報表檔含機密等級的營運資料，與資料庫同級。生產環境務必至少啟用加密與異地其一， 否則備份等於一份明文機密資料落在單一台機器上。

還原

# 1. 停止應用程式
systemctl stop smartfactory

# 2a. 資料庫（未加密）
pg_restore --clean --if-exists -d "$PGDATABASE" <備份檔.dump>
# 2b. 資料庫（已加密）
gpg --decrypt <備份檔.dump.gpg> | pg_restore --clean --if-exists -d "$PGDATABASE"
# 2c. 檔案（解到 reports/、uploads/ 的「父目錄」）
tar -xzf <備份檔-files.tar.gz> -C <目標父目錄>

# 3. 啟動並驗證
systemctl start smartfactory && curl -f http://localhost:5000/health
資料庫與檔案必須取自同一次執行（檔名時間戳相同），否則 ReportRun 列與實際檔案對不上。 --clean 會先 DROP 再重建，請再三確認目標資料庫。 若是要回滾某次 migration，還原後必須部署對應舊版的應用程式，並確認生產組態的 Database:AutoMigrate 為 false，否則新版一啟動又把 schema 推回去。

備份排程建議

  • 每日排程：30 2 * * * /path/to/repo/scripts/backup-db.sh >> /var/log/smartfactory-backup.log 2>&1
  • 每次 migration 前手動再跑一次
  • 每小時：WAL 串流複製（若有高可用需求）
  • 上線前：備份一份 baseline，存放離線媒體
  • 每季做一次還原演練：確認加密備份真的解得開、檔案包真的解得回去——沒演練過的備份不算備份
