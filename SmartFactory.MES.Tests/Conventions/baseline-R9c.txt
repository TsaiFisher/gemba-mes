# R9(c) baseline — 數量欄位寫死整數 step／min 的「刻意保留」清單（won't-fix），以檔案路徑為鍵。
# 不在此清單的新違規會讓建置失敗。
#
# R9(c) 擋的是「小數單位的品號在畫面上輸不進去」：step="1" 與 min="1" 會讓瀏覽器原生
# 驗證直接拒收 0.5，而伺服端（RoundQtyAsync）本來就按單位精度收數量——畫面比伺服端嚴，
# 且沒有任何訊息指向真正的原因。
#
# 唯一的合法例外是「語意上就是整數，不跟隨 UOM 精度」的欄位：
#   InspectionOrder/_Details：ActualSampleQty（實際抽樣數）、FailQty（不良數）
#     ——抽樣是「抽幾件」、不良是「幾件不良」，都是計件，沒有 0.5 件這回事。
#     它們也不屬於任何 UOM：檢驗單的樣本數與受檢品的計量單位無關。
#
